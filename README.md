# Список сотрудников

Небольшое full-stack приложение: регистрация и вход, защищённый список сотрудников, поиск по ФИО и фильтр по отделу. Данные хранятся в SQLite и остаются после перезапуска сервера. В профиле можно загрузить фото или создать сгенерированный аватар.

## Стек

- Frontend: React, TypeScript, Vite, FSD, обычный CSS, Tailwind CSS v4 для компонентов Kokonut UI, Anime.js.
- Backend: Node.js, Express, TypeScript.
- Хранение: SQLite (`better-sqlite3`). Пароли хешируются с помощью bcrypt, API защищено JWT.

## Структура клиента

- `pages/` содержит страницы входа и справочника. Они подключаются через `React.lazy`, поэтому Vite собирает отдельные чанки страниц.
- `entities/employee/api` и `entities/user/api`, а также `features/auth/api` содержат запросы по соответствующим доменам. HTTP-клиент с обработкой ошибок и токеном находится в `shared/api`.
- Стили страниц и компонентов оформлены CSS Modules рядом с TSX. Глобальный `app/styles.css` оставлен для сброса, токенов темы и общих элементов.
- `lib/utils.ts` экспортирует `cn` на основе `clsx` и `tailwind-merge` для условных классов.

## Структура сервера

Серверные файлы сгруппированы по функциям. Внутри каждой папки рядом лежат маршруты, контроллер, сервис и репозиторий:

```text
server/src/
├── features/
│   ├── auth/
│   │   ├── auth.routes.ts       # URL и middleware
│   │   ├── auth.controller.ts  # HTTP-запросы и ответы
│   │   ├── auth.service.ts     # правила регистрации и профиля
│   │   └── auth.repository.ts  # SQL-запросы пользователей
│   └── employees/
│       ├── employees.routes.ts
│       ├── employees.controller.ts
│       ├── employees.service.ts
│       └── employees.repository.ts
├── config/                     # переменные окружения
├── db/                         # подключение и схема SQLite
├── middleware/                 # JWT-аутентификация
├── shared/                     # общие типы HTTP
└── index.ts                    # запуск Express
```

Контроллеры отвечают за HTTP, сервисы — за проверки и правила, репозитории — за SQL. Так запросы к базе не смешиваются с обработкой маршрутов.

Интерфейс профиля использует компоненты [Kokonut UI](https://kokonutui.com/): Account Menu, Avatar Picker и File Upload. Исходники компонентов находятся в `client/src/components/kokonutui/`.

## Запуск

Нужны Node.js 20+ и npm.

1. Установите зависимости из корня проекта:

   ```bash
   npm install
   ```

2. Создайте `server/.env` (секрет замените на случайную строку длиной не менее 32 символов):

   ```env
   PORT=4000
   JWT_SECRET=replace-with-a-long-random-secret-at-least-32-chars
   CLIENT_ORIGIN=http://localhost:5173
   ```

3. Запустите сервер и клиент:

   ```bash
   npm run dev
   ```

4. Откройте <http://localhost:5173> и зарегистрируйте пользователя. API работает на <http://localhost:4000>.

Для production-сборки выполните `npm run build`, затем `npm start` (сервер). Клиентскую папку `client/dist` нужно раздавать статическим хостингом.

## Домен

Для GitHub Pages используется домен `workers-names.ru` (без протокола). Файл `CNAME` в корне репозитория фиксирует домен для публикации из ветки, а `client/public/CNAME` попадёт в корень Vite-сборки `client/dist`.

GitHub Pages обслуживает статический клиент. Для работы регистрации и списка сотрудников Express API и SQLite-сервер нужно будет разместить отдельно; база остаётся локальной для этого сервера.

Проверка стиля и потенциальных ошибок: `npm run lint` (ESLint).

## Демонстрационные данные

В Git хранится чистый шаблон SQLite `server/data/employees.template.sqlite` с пятью демонстрационными сотрудниками и без учётных записей. При первом запуске сервер копирует его в локальную `server/data/employees.sqlite`; дальнейшие пользователи и изменения сохраняются только в локальной базе, исключённой из Git. Если шаблона нет, сервер создаёт схему и добавляет пять сотрудников автоматически. Список доступен только после входа.

## API

- `POST /api/auth/register` — регистрация по email и паролю.
- `POST /api/auth/login` — вход.
- `GET /api/employees` — поиск (`q`) и фильтр (`department`), требует `Authorization: Bearer <token>`.
- `POST /api/employees` — добавить сотрудника, требует авторизации.
- `GET /api/departments` — отделы для фильтра, требует авторизации.
- `GET /api/auth/me` и `PATCH /api/auth/profile` — сведения профиля и фото профиля, требуют авторизации.
